# fcitx5-windinput-git

清风输入法 **WindInput** — an open-source Chinese input method (五笔/拼音/双拼), packaged
for Arch Linux / CachyOS as a **Fcitx5 engine built from source**. Maintainer:
**Yang <shareur@imyang.me>**. Tracks upstream `main` (`0.130.1.r41.gc70da4c-1` at the time
of writing).

[简体中文](../../docs/zh-cn/packages/fcitx5-windinput-git/README.md)

## What this package is

WindInput's Linux port runs as a Fcitx5 input method engine. Upstream ships a `.deb`;
there is **no upstream AUR package** (`docs/design/linux-port.md` records Arch/PKGBUILD as
"not yet done"). The existing AUR `fcitx5-windinput-bin` repacks that `.deb`. This recipe
instead builds everything from the upstream Git repositories:

| Component | Source | Installed path |
| --- | --- | --- |
| Engine service (Rust, `wind_input`) | `huanfeng/WindInput` | `/usr/lib/windinput/wind_input` |
| Runtime data (dictionaries, OpenCC tables, …) | generated by `scripts/dev.sh gd` | `/usr/lib/windinput/data/` |
| GUI settings (`wind_setting`) | `huanfeng/wind-setting` (+ `wind-ui-rust`) | `/usr/lib/windinput/wind_setting` |
| Fcitx5 addon (C++, `libwindinput.so`) | `huanfeng/WindInput` (`wind_linux/`) | `/usr/lib/fcitx5/libwindinput.so` |
| addon / input-method descriptors | `wind_linux/data/*.in` | `/usr/share/fcitx5/{addon,inputmethod}/windinput.conf` |

The engine, dictionaries and candidate rendering live in the Rust service; the addon only
forwards keys and writes back commits/pre-edits, and draws the self-rendered candidate
window. The service locates `data/` next to its executable, which is why it installs into
`/usr/lib/windinput/` (identical to the vendor `.deb`).

## Install

```bash
sudo pacman -S --needed base-devel rust cmake pkgconf git curl python
git clone https://github.com/shareur/aur-packages.git
cd aur-packages/packages/fcitx5-windinput-git
makepkg -si
```

`makepkg` must run as a regular user. This is a `-git` recipe: the first build clones three
upstream repositories and compiles the full Rust workspace (release) plus the C++ addon, and
generates the dictionary data — expect a long first build. Afterwards, in **Fcitx5
configuration** (`fcitx5-configtool`) add **清风输入法 / WindInput** to the input method list.
After upgrades run `fcitx5 -rd` (or log out and back in); `pacman` upgrades while Fcitx5 is
running leave the old addon loaded until then.

Remove with `sudo pacman -R fcitx5-windinput-git`. User configuration
(`~/.config/WindInput`) and user data (`~/.local/share/WindInput`) are never touched.

## Differences from the vendor `.deb`

- **No Debian maintainer scripts.** The vendor `postinst`/`postrm` kill the old
  `wind_input` service on upgrade. pacman does not run them, so this package does not either;
  the addon relaunches a fresh service when it cannot connect, and a running Fcitx5 keeps the
  previously loaded addon until restarted (`fcitx5 -rd`). This is stated in the upgrade note
  above rather than done silently by a script.
- **`compat.toml` is the Linux variant.** Upstream's `data/compat.toml` carries
  Windows-host-only compatibility rules. As the `.deb` does, `scripts/lib/gen-compat.sh`
  regenerates the Linux file (field documentation + zero built-in rules) at package time.
- **Dependencies are Arch names.** Debian `Depends`/`Recommends` are remapped to Arch
  packages, and the linked libraries are checked with `ldd`; see below.

## Dependencies

Required: `fcitx5` (the engine framework and its addon CMake/headers), `glibc`, `gcc-libs`,
`libxcb` (X11 candidate window via xcb/shape/randr), `wayland` (Wayland candidate window),
`glib2` (GNOME caret-extension client via gio), `fontconfig` (opened at runtime by the service
and used by the settings renderer), `libxkbcommon`, `hicolor-icon-theme`.

Optional: `fcitx5-gtk` / `fcitx5-qt` (input front-ends for GTK/Qt apps), `xclip` (X11
clipboard) or `wl-clipboard` (Wayland clipboard), `xdg-utils`, `xdg-desktop-portal` +
`zenity` (file dialogs in the settings app), `noto-fonts-cjk` (CJK candidate glyphs),
`noto-fonts-emoji` (emoji candidates).

The Fcitx5 addon binds to the distribution's `fcitx5` ABI; because this is a `-git` package it
is rebuilt against your installed Fcitx5, so it also picks up Arch's newer (5.1.x) headers
with C++20 automatically.

## Reproducibility and network access

The runtime dictionaries are **not** checked into upstream's Git tree. `scripts/dev.sh gd`
assembles them by downloading raw dictionaries from several upstream repositories at build
time (`gaboolic/rime-frost`, `mozillazg/pinyin-data`, `BYVoid/OpenCC`,
`KyleBing/rime-wubi86-jidian`, plus optional `rime-stroke`/`rime-emoji`/Unicode CLDR), then
deriving tables with the bundled `wind-tools` Rust binaries and a `python3` script
(`scripts/comment_dicts`). Those upstream URLs are currently **not pinned to a commit or
version**, so two builds made at different times can differ. This recipe therefore does **not**
claim reproducible or offline builds. Pinning those data sources (fixed commits with a
pre-seeded `.cache/`) is the intended follow-up.

The application source itself is fetched from the three Git repositories above (VCS sources,
`SKIP` checksums, tracking their default branch — normal for a `-git` package).

## Known limitations

- **Preview status.** Upstream labels the Linux port a preview/beta.
- **GNOME (Wayland):** native cursor positioning needs the shipped Shell extension
  (`windinput-caret@windinput`); this recipe does not enable it for you.
- **KDE Plasma (Wayland):** select **Fcitx 5** under *System Settings → Keyboard → Virtual
  Keyboard* and re-login; do **not** set `QT_IM_MODULE`/`GTK_IM_MODULE` for native Wayland
  apps. See upstream `wind_linux/README.md` (installed to `/usr/share/doc/windinput/`).
- A fresh app starts in the keyboard layout unless *Shared Input State* is set to *All* in
  Fcitx5 global options.

## Verification and limits

From the repository root:

```bash
bash scripts/validate.sh fcitx5-windinput-git          # sources, build, .SRCINFO, namcap, layout, sha256
bash scripts/test-local-install.sh fcitx5-windinput-git # interactive sudo; install/check/remove/restore
```

`check-package.sh` verifies the addon install path and descriptors, the presence and minimum
size of the key dictionaries (matching upstream's release gate in `scripts/dev.sh`,
`verify_dist_data`), that OpenCC produced at least one `.octrie`, that `compat.toml` carries
no built-in rules, desktop-entry syntax, and the absence of Debian packaging leftovers.
`test-install.sh` installs the package and confirms the three ELF files (`wind_input`,
`wind_setting`, `libwindinput.so`) have no unresolved shared libraries, then removes it and
checks for leftovers.

Not covered here: an interactive desktop session actually typing through Fcitx5, candidate
window rendering on X11 vs Wayland, the GNOME Shell extension, `im-config`/desktop
integration, and reproducible builds. A successful build and install is not evidence for any
of these.
