# Validation: fcitx5-windinput-git 0.130.1.r41.gc70da4c-1

- Upstream: huanfeng/WindInput branch main. Latest release tag is v0.130.1 (be9347de); this build is main HEAD c70da4c, 41 commits later. pkgver from git describe is 0.130.1.r41.gc70da4c.
- Companion sources: huanfeng/wind-setting and huanfeng/wind-ui-rust (branch main). wind_setting is a separate repository whose Cargo.toml has path dependencies on ../wind-ui-rust and ../WindInput/wind_input/crates/*, so all three are checked out as siblings.
- Runtime data is NOT in the upstream Git tree. scripts/dev.sh gd downloads dictionaries at build time from gaboolic/rime-frost, mozillazg/pinyin-data, BYVoid/OpenCC and KyleBing/rime-wubi86-jidian (plus optional rime-stroke, rime-emoji and Unicode CLDR), then derives tables with the wind-tools Rust binaries and scripts/comment_dicts (python3). Those URLs are not pinned to a commit, so builds are not reproducible; this is recorded in the package README.
- Build host: CachyOS x86_64, fcitx5 5.1.23-1.1 (Arch headers require C++20; the addon CMake detects and upgrades automatically), cmake 4.4.5, gcc 16.2.1, python 3.14.9. rustc and cargo 1.99.1 were installed per-user via rustup because the pacman rust package could not be installed without a password prompt.
- Command run: makepkg --nodeps --force --noconfirm. nodeps was used because rust was provided by rustup rather than a pacman package and ninja/namcap were absent. CMake used the default Make generator; the recipe does not require ninja.
- Build result: gen-data assembled build_dev/data (92 files, 43176522 bytes). wind_service (binary wind_input), wind_setting and the C++ addon all built. Package fcitx5-windinput-git-0.130.1.r41.gc70da4c-1-x86_64.pkg.tar.zst is 32787043 bytes; installed size is 82050470 bytes by du and 81970270 by PKGINFO.
- Linker issue found and fixed: the host makepkg OPTIONS included lto, and /usr/share/makepkg/buildenv/lto.sh appends -flto=auto to CFLAGS/CXXFLAGS/LDFLAGS. The cc crate then compiled ring (the settings app TLS stack via rustls and ureq) as GCC LTO objects, while rustc links without -flto, so the linker reported undefined ring_core_0_17_14 symbols. Adding options with !lto to the PKGBUILD fixed the link. Rust -C lto is unaffected by that option (off by default). A manual cargo build of wind_setting with CFLAGS unset linked successfully, confirming the cause.
- check-package.sh: exit 0. It verified the addon at usr/lib/fcitx5/libwindinput.so, the addon descriptor Library=libwindinput, the input-method descriptor Addon=windinput, the private payload paths, a compat.toml with zero rule tables, at least one non-empty OpenCC octrie, and these dictionary sizes: base.dict.yaml 9937947, 8105.dict.yaml 99367, en.dict.yaml 339551, pinyin_map.txt 963878, wubi86_jidian.dict.yaml 1439572, wubi86_jidian_extra.dict.yaml 32432, wubi86_jidian_extra_district.dict.yaml 87886, comments zh_en.txt 4257010. desktop-file-validate emitted one hint only: windinput-setting.desktop Categories lists two main categories.
- ELF NEEDED: wind_input needs libgcc_s, libm and libc. wind_setting needs libgcc_s, libm and libc; windui opens fontconfig, xkbcommon and the display libraries dynamically. libwindinput.so needs libFcitx5Core.so.7, libFcitx5Config.so.6, libFcitx5Utils.so.2, libxcb, libxcb-shape, libxcb-randr, libwayland-client, libgio-2.0, libgobject-2.0, libglib-2.0, libstdc++, libm, libgcc_s and libc. ldd reported no missing libraries for all three. Declared depends (fcitx5, libxcb, wayland, glib2, glibc, gcc-libs) cover the NEEDED set; fontconfig and libxkbcommon are declared because they are opened dynamically.
- The GNOME Shell caret extension is shipped at usr/share/gnome-shell/extensions/windinput-caret@windinput because gio-2.0 was present during the build. It is installed but not enabled.
- Not run: scripts/validate.sh as a whole, namcap, and scripts/test-local-install.sh. validate.sh checks dependencies as pacman packages and runs namcap, and test-local-install.sh installs to the host via sudo; neither could run without root package installation. These remain for CI in an archlinux base-devel container.
- Not tested: interactive typing through Fcitx5, X11 and Wayland candidate-window rendering, the GNOME Shell extension being enabled, desktop-session integration, upgrade behaviour while Fcitx5 is running, and reproducible builds.
- CI failure for commit 78e7a11 happened in the namcap step, not the build. The default Arch makepkg.conf enables debug, so a fcitx5-windinput-git-debug package was built too; namcap flagged its /usr/lib/debug/.build-id symlinks as pointing to non-existing files, because those symlinks target binaries inside the main package, which is not installed at that point. The recipe now sets options to disable debug, so no debug package is produced; verified that makepkg --packagelist with a debug-enabled makepkg.conf lists only the main package. The gdb-add-index No debugging symbols warnings in the same log are cosmetic and disappear with !debug.
- CI confirmation: the fix was validated by GitHub Actions run 42453303478 (commit d961622), which completed successfully; the fcitx5-windinput-git job passed build, lint, install, smoke and removal.
